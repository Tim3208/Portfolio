# Design Guide

이 문서는 포트폴리오의 시각 시스템과 인터랙션 규칙을 정리한다. 기준 소스는 [globals.css](../src/app/globals.css), [hue.ts](../src/lib/hue.ts), [theme.ts](../src/lib/theme.ts), [browser components](../src/components/browser), [Contact](../src/components/layout/Contact.tsx), [Footer](../src/components/layout/Footer.tsx), [og.ts](../src/lib/og.ts)다.

AGENTS 원문은 `--paper`, `--ink`처럼 짧은 토큰 이름을 쓴다. 실제 구현은 Tailwind v4 `@theme` 토큰이므로 대부분 `--color-paper`, `--color-ink`처럼 `--color-*` 접두사를 붙인다. 이 문서는 실제 구현 이름을 우선하고, 필요한 경우에만 원문 축약 이름을 함께 적는다.

## 디자인 3안: 주석 단 실물 화면

`design/3-claude` 브랜치의 도색 시안이다. 스케치(`sketch/browser-remake`) 위에서 2026-10-10 리디자인 제안 초안(DESIGN.md, PROPOSED)의 흐름을 우선해 칠했다. 1안(연구 노트)·2안(형광펜)과 달리 팔레트를 새로 만들지 않고, 이 문서에 보존해 둔 Cloud Dancer · Earthen Pastels 토큰을 그대로 되살렸다. 이 안을 채택하지 않으면 이 절을 지우고 스케치 기준으로 돌아간다.

색은 2026-11-18에 다시 정했다. 크림 지면과 서로 구분되지 않는 갈색 여섯이 화면 전체를 한 가지 색으로 보이게 해서, 중성 지면에 색상이 다른 여섯 계열을 올리는 값으로 바꿨다. 토큰 이름과 쓰는 규칙은 그대로이고 값만 [Color](#color) 이하의 표로 바뀌었다.

- **핵심 표현**: 실제 스크린샷 위에 번호 점을 찍고, 화면 아래 같은 번호의 목록으로 그 자리에서 내린 판단을 적는다([Shot](../src/components/ui/Shot.tsx), 주석 원본은 [annotations.ts](../src/data/annotations.ts)). 목록이 항상 보이므로 조작하지 않아도 읽히고, 한쪽에 포인터를 올리면 짝이 함께 강조된다. 화면에는 다른 브라우저 크롬이나 기기 프레임을 덧씌우지 않는다.
- **선택적 체험**: 한 번에 한 상태를 고르는 [Switcher](../src/components/ui/Switcher.tsx)를 대표 프로젝트 행의 화면 전환과 기존 두 재구성 데모가 함께 쓴다. 라디오 묶음이라 서버 렌더 그대로 JS 없이 동작한다. 실제 코드를 실행하는 데모는 클라이언트에서 동작한다. 스탬프·결과 확인의 상황 선택 줄은 Switcher와 모양을 공유하고, 삼육대 어디야는 직접 검색 입력과 예시 검색어 버튼을 쓴다. 데모 목록은 [아래](#option-3-demos)에 있다.
- **창과 폭**: 창은 최대 `110rem`(1760px), 바깥 여백 12 · 16 · 20px, 크롬은 탭줄 + 도구줄 2행이다. 예전 북마크바의 주요 페이지 링크는 도구줄 오른쪽으로 옮겼다(768–1023px에서는 GitHub 링크만 본문 · 연락처에 맡긴다). 본문 전체의 최대 폭은 없애고 섹션 거터(16 · 24 · 32px)를 [Container](../src/components/ui/Container.tsx) 한 곳에서만 준다. 긴 문단만 `max-w-measure`(672px)를 지킨다.
- **색**: 섹션마다 `.hue-*` 하나. 프로젝트 색은 선택 상태, 화면 주석 점, 도식의 연결, 라벨, 포커스링에만 쓰고 실제 스크린샷의 색은 바꾸지 않는다. Contact · Footer는 `deep-ground` 반전 블록이고 Footer 맨 아래에 여섯 색 색표본을 둔다.
- **화면이 없을 때**: 공개할 실제 화면 캡처를 확보하지 못한 대표 프로젝트는 목업 대신 담당 범위 도식(내가 구현한 화면 / 팀원 · 백엔드)을 대표 자리에 둔다. Make A Wish는 상세 스탬프를 원본 코드 실행 데모로 보여주고, HERO 칸에는 그 데모의 서비스 화면 캡처(샘플 데이터)를 쓴다. 대표 행은 확보 전이라 담당 범위 도식을 유지한다. 상세 지도처럼 남은 빈 이미지 블록은 [Placeholder](../src/components/ui/Placeholder.tsx)의 "확보할 화면"으로 둔다. 확보할 화면은 방문자에게 적지 않고 데이터(`cover.alt`)와 TODO에 남긴다.
- **아이콘**: 포트폴리오 UI의 크롬 컨트롤(뒤로 · 앞으로 · 새로고침 · 닫기 · 새 탭 · 테마)에만 의존성 없는 선 아이콘([icons.tsx](../src/components/browser/icons.tsx))을 쓰고, 이름은 접근 이름과 툴팁이 글자로 말한다. 옮긴 스탬프 화면의 뒤로 아이콘은 원본 모양을 유지한 장식이다.
- **모노 폰트**: 주소창, 날짜 · 연도, 코드 · 식별자, 비교 수치에만 쓴다. 한글이 섞인 라벨과 "2026.01 — 현재" 같은 기간은 Pretendard의 tabular 숫자로 쓴다.

### 설명용 데모

- 기존 두 재구성 데모의 패널은 한 칸에 겹쳐 높이가 흔들리지 않고, 숨긴 패널은 `visibility`로 접근성 트리와 Tab 순서에서 빠진다. 전환은 180ms 투명도이고, `prefers-reduced-motion: reduce`에서는 즉시 바뀐다. `:has()`를 모르는 브라우저에서는 첫 상태만 보인다.
- 평가 단계 데모에서 면접 단계의 목록을 "서류 합격자 목록"으로 둔 것은 설명용 재구성이다. 실제 명세의 필드 · 목록과 일치하는지는 확인이 필요하다.

#### 실제 코드 실행 데모의 공통 기준

실제 코드 실행 데모를 추가하거나 스크린샷 자리를 데모로 바꿀 때 따르는 기준이다(2026-11-19 결정).

- **고르는 기준**: 실제 서비스에서는 방문자가 만들 수 없는 장면이 있는 자리만 데모로 바꾼다. 로그인 뒤 화면, 잘못된 응답, 시간이 지난 뒤의 상태, 결과가 그렇게 나온 이유가 여기에 든다. [라이브 탭](#live)으로 그대로 열리는 화면을 다시 만들지 않는다.
- **옮기는 방식**: 화면 컴포넌트와 순수 로직은 원본을 최소 수정으로 옮기고, 파일마다 원본 경로 · 기준 커밋 · 변경점을 적는다. 서버 조회 · 라우터 · 인증만 샘플 데이터로 바꾼다. 원본에 없는 조작은 서비스 화면 밖 패널에만 둔다. 비슷하게 다시 그린 것은 이 종류가 아니라 설명용 재구성이다.
- **기본 상태**: 조작하지 않아도 기본 상태만으로 무슨 화면인지 읽혀야 한다. 날짜에 기대는 화면은 "오늘"을 고정값으로 넣어 언제 열어도 같은 장면이 나오게 한다.
- **색 · 폰트**: 옮긴 화면은 스크린샷처럼 서비스의 색 · 폰트를 유지한다. 서비스 토큰은 화면 루트의 범위 변수(`--maw-*`처럼 서비스마다 다른 접두어)에 두고 전역 `@theme`에 넣지 않는다.
- **터치 영역**: 44px 터치 영역은 포트폴리오 쪽 패널 컨트롤의 기준이고, 옮긴 서비스 화면은 원본 크기를 유지한다.
- **에셋**: 필요한 것만 `public/images/projects/<slug>/` 아래에 두고, 데모 하나의 에셋 합계는 500KB 이하를 목표로 한다. 넘으면 줄이거나 이유를 적는다. Oshi Calendar의 게임사 로고처럼 제3자 그림은 저장소 주인의 결정(2026-11-19)으로 서비스 화면 안에서만 쓰고, 출처는 [콘텐츠 기준](content.md)에 적는다.
- **공동 작성 코드**: 팀원이 쓴 코드가 섞인 화면은 본문과 `ownership`에 공동 작성임을 밝히고 옮긴다. syu-likelion 평가 화면이 해당한다(2026-11-19 결정). 본인 기여가 아닌 기능 자체를 데모로 만들지는 않는다.
- **실행 경계**: 공통 틀에서 클라이언트 경계는 훅이 필요한 [DeferredDemoFrame](../src/components/project/demos/shell/DeferredDemoFrame.tsx)뿐이다. 표면 · 배치 · 패널은 클라이언트 선언 없이 두고, 상태와 이벤트는 데모별 클라이언트 컴포넌트가 소유한다.
- **불러오기**: 서비스 화면은 `DeferredDemoFrame`으로 화면 가까이 왔을 때 한 번 마운트하고, 그 전에는 같은 크기의 빈 프레임으로 자리를 지킨다. 프레임의 폭과 빈 자리 마크업은 각 데모가 넘긴다. `IntersectionObserver`는 `root: null`, `rootMargin: "240px 0px"`로 문서와 중간 스크롤 조상인 데스크톱 `Viewport`의 교차 영역을 함께 확인하고, 지원하지 않으면 바로 마운트한다.
- **틀**: 표면 · 표시 문구 · 캡션, 지연 마운트, 패널과 모바일 조작 막대는 [shell](../src/components/project/demos/shell)의 공통 틀을 쓴다. 틀은 자리만 제공하고 데모별 내용을 설정값으로 흡수하지 않는다. `DemoSurface`는 색 계열 · 표시 문구(기본값 "실제 서비스 코드 · 샘플 데이터") · 캡션 · 본문, `DemoLayout`은 자식과 넓은 화면의 `variant="wide"`, `DemoPanel`은 접근 이름 · 안내 · 조작 묶음과 선택적인 일반 본문(`body`) · 응답(`response`)을 받는다. 일반 본문은 접지 않고 흐름에 두며, 응답을 넘긴 경우에만 틀이 `details`를 만든다. 응답의 `summary`와 JSON 본문은 데모가 넘긴다.
- **표면과 배치**: 표면은 `figure`와 `figcaption`, `rounded-xs border border-rule bg-paper-raised`, 안쪽 여백 16·24px을 쓴다. 서비스 프레임에는 얇은 테두리만 두며 기기 목업 · 그림자 · 새 모션을 더하지 않는다. 기본 배치는 `md` 이상에서 화면 · 패널 2열이고 화면의 폭 제한은 각 데모가 정한다. 패널은 위쪽에 sticky로 두며, 제목과 안내는 일반 흐름에 놓는다.
- **넓은 화면 프레임**: 원본이 브라우저 폭으로 데스크톱 모양을 고르는 화면은 `DemoLayout`과 `DeferredDemoFrame`의 `wide` 배치를 쓴다. 패널을 위, 서비스 화면을 아래에 놓고 `md` 이상 패널은 한두 줄로 낮게 둔다. 기본 동작은 `lg` 이상에서 데모가 정한 고정 설계 폭으로 그린 뒤 `zoom`으로 프레임 폭에 맞춰 줄여, 줄인 크기가 레이아웃에 반영되게 한다. 높이는 `--viewport-height`에서 패널 높이를 뺀 만큼으로 제한하고 안쪽에서 세로로 스크롤한다. 프레임은 접근 이름과 초점을 받아 키보드로 스크롤할 수 있어야 하며, 상황이 바뀌면 맨 위로 돌아간다. `lg` 미만에서는 최대 폭을 휴대폰 정도로 제한해 가운데 두고, 축소와 안쪽 스크롤 없이 원본 모바일 화면을 흐르게 한다. 좁은 화면용 배치가 없는 서비스는 `scaleAtAllWidths`로 모든 폭에서 줄이는 선택지를 쓴다. 이때 고정 설계 폭·높이로 그린 전체 화면을 프레임 폭에 맞추고, `lg` 이상에서는 가용 높이도 함께 고려해 프레임 자체의 세로 스크롤 없이 화면 전체를 넣는다. 화면 내부 구역의 원본 스크롤은 유지하고, 좁은 폭에서 조작을 허용할지는 데모가 정한다. 상황 변경 후 프레임 위쪽이 화면 밖에 있으면 위쪽이 보이게 맞춘다. 설계 폭·높이·접근 이름·전환 키는 데모가 `designWidth`·`designHeight`·`label`·`resetKey`로 넘긴다. 기존 결과 확인 데모는 기본 동작을 유지한다.
- **모바일 조작 막대**: `md` 미만은 같은 조작 묶음을 데모 범위 안 아래쪽의 sticky 막대로 줄인다. 제목 · 안내 · 일반 본문과 응답 보기는 막대 밖 일반 흐름에 둔다. 모바일 패널은 `display: contents`로 두어 조작 막대의 sticky 범위가 서비스 화면까지 이어지게 한다.

- **검색과 선택**: 기본 검색어는 `장근청홀`이고 결과와 선택한 장소 카드를 처음부터 보여준다. 입력·초점 때만 드롭다운을 열고 최대 10개, Enter로 첫 결과 선택, Escape·바깥 누름으로 닫기를 유지한다. 전체·건물·건물 내부 필터와 주요 장소 8개를 두며, 선택하면 원본처럼 카드와 검색창 이름이 바뀐다.
- **순서 설명**: 화면 밖 패널 제목은 "왜 이 순서인가", 안내는 "검색어가 어느 필드에 어떻게 일치했는지로 점수를 매기고, 점수가 낮을수록 위에 옵니다."다. 현재 분류 필터를 따른 위쪽 5개까지 순위·이름·일치 필드·완전 일치/앞부분 일치/포함·점수를 보여준다. 여러 층에 반복된 시설의 빈도 보정도 표시한다. 원본 `searchPlaces`의 계산·정렬은 바꾸지 않고 필드 이름표와 별도 `explainSearchPlaces`만 더해 같은 순서·점수를 설명한다. 빈 검색어는 "검색어를 입력하면 순서의 이유가 여기에 나옵니다.", 0건은 "일치하는 필드가 없습니다. 오타는 보정하지 않습니다."로 안내하고 갱신은 `aria-live="polite"`로 알린다.
- **표면과 배치**: 색 계열은 프로젝트의 `sage`, 표시 문구는 "실제 서비스 코드 · 원본 장소 데이터"다. 기본 2열 배치를 쓰고 원본 왼쪽 열에 맞춰 서비스 프레임의 최대 폭은 420px, 최소 높이는 48rem(768px)으로 둔다. 포트폴리오 캡션은 "검색 결과의 순서는 일치한 필드와 일치 정도로 정해집니다. 지도는 빼고 검색 패널만 옮겼습니다."다. 상세 03의 판단 뒤에 데모를 더하고 상세 04의 검색·지도 스크린샷은 유지한다.
- **예시와 모바일 조작 막대**: `장근청홀`·`학생식당`·`편의점`·`프랜들리`·`중앙 도서관`·`총장실`·`중앙도서곤` 버튼으로 검색어를 넣는다. 마지막은 0건인 오타 예시다. `md` 미만에서는 버튼을 44px 터치 영역의 한 줄 sticky 조작 막대로 두고 넘치는 버튼은 가로 스크롤한다. 순서 설명은 `DemoPanel`의 일반 본문에 두어 막대 밖에서 읽힌다.
- **서비스 색·폰트와 Tailwind 3 이식**: 서비스 화면은 포트폴리오의 다크 테마에서도 밝은 원본을 유지한다. 원본 `brand`와 Tailwind 3 기본 회색은 화면 루트의 `--eodiya-*` 변수로 격리하며 전역 `@theme`에 더하지 않는다. 테두리·구분선의 `gray-200` 기본값과 shadow·radius·outline·ring의 원본 크기를 Tailwind 4에서 맞춘다. 원본에 별도 웹 폰트가 없어 Tailwind 3 기본 `ui-sans-serif`·`system-ui` 계열과 행간 1.5·일반 줄바꿈을 화면 범위에 유지한다.

Oshi Calendar 바꾸기 전 첫 화면 데모의 기준은 다음과 같다. 원본·샘플 일정·게임 그림의 근거는 [콘텐츠 기준](content.md#oshi-calendar)에 둔다.

- **실행 경계**: [CalendarFirstDemo](../src/components/project/demos/CalendarFirstDemo.tsx)는 서버에서 표면을 조립하고, [CalendarFirstControls](../src/components/project/demos/CalendarFirstControls.tsx)가 고정 "오늘"과 서비스 화면 상태를 맡는다. 옮긴 화면·날짜 계산·묶음·필터·샘플 일정은 [oshi-calendar](../src/components/project/demos/oshi-calendar)에 둔다. 기준 커밋은 `40c516b`이며 게임 허브 | 임박 일정 | 가운데 캘린더의 3열을 유지한다. 서버 조회는 샘플 일정으로 바꾸고 인증·설정의 localStorage 및 서버 저장은 제외해 메모리 상태만 쓴다. 정상 상태만 보여주되, 서버가 없는 샘플 일정이므로 임박 일정과 캘린더의 "실제 데이터 · 서버 일정" 정상 안내는 데모 조립부에서 상태를 넘겨 숨긴다. 로딩·오류·빈 결과 안내 코드는 보존한다.
- **원본 조작**: 원본 기본값은 주간이며, 데모는 기간 막대가 겹치는 모습을 처음부터 보여주도록 월간 보기를 초기값으로 넘긴다. 월·주·일 전환, 이전·다음·오늘, 미니 캘린더 날짜 선택, 임박 일정 접기, 게임 켜고 끄기·추가, 분류 필터와 일정 칩·보상 표시를 유지한다. 원본 로그인 영역은 옮기지 않는다. 바꾼 뒤 작업 공간·할 일·보상 통계·관리자 콘솔은 범위 밖이다.
- **고정 오늘과 샘플 일정**: 처음 "오늘"은 `2026-07-16T12:00:00+09:00`(목요일 12시, 한국 시간)이다. 7월 12–18일 주간과 앞뒤에 걸친 공식 공지 일정 22건을 쓰며, 엔드필드 10·스타레일 4·명조 4·젠레스 3·원신 1건이다. 기본 상태에서 종료 전 일정 6건이 임박 목록에 남고 같은 주 캘린더에 긴 일정이 겹친다. 당일 07시에 끝난 일정과 12시 59분에 끝나는 일정을 함께 두어, 날짜 칸에서는 같아 보이는 종료 시점과 남은 시간을 견주기 위해 이 시각을 골랐다. 실제 현재 시각이나 원본 `useCurrentTime`은 사용하지 않고 날짜 계산·필터·오늘 표시에 패널의 시각을 넘긴다.
- **설계 크기와 축소**: 좁은 화면용 배치가 없는 원본을 `1280 × 800px`로 그린다. 원본의 `100svh`와 `clamp(16px, 3.125vw, 60px)` 바깥 여백은 설계 크기 기준으로 고정해 여백 40px, 안쪽 크기 `1200 × 720px`을 쓴다. 원본 `max-xl:`의 `300px | minmax(248px, 280px) | minmax(0, 1fr)` 3열과 캘린더 격자의 최소 폭·열 폭을 유지하며, 캘린더는 자기 칸 안에서 가로로 스크롤한다. 반응형 분기는 실제 브라우저 폭이 아닌 설계 폭을 기준으로 적용하므로 브라우저가 1920px이어도 같은 배치다. `wide` 배치에서 `scaleAtAllWidths`와 `designHeight`를 넘겨 모든 폭에 맞춰 줄이되 최대 1배로 제한한다. `lg` 이상은 가용 높이까지 고려해 프레임 안 세로 스크롤 없이 화면 전체를 보여준다. 화면 내부 구역의 스크롤은 원본 그대로다.
- **좁은 화면**: `lg` 미만은 전체 모습을 보여주는 용도다. 서비스 화면을 `inert`로 두어 내부 컨트롤을 Tab 순서와 터치 대상에서 빼고, 프레임 아래 "넓은 화면에서는 캘린더와 게임 허브를 직접 조작할 수 있습니다."를 표시한다. 화면 밖 패널의 날짜 이동은 계속 동작한다. `md` 미만의 조작 묶음은 기존 넓은 화면 배치처럼 sticky 조작 막대로 둔다.
- **패널과 표면**: 제목은 "같은 일정, 두 가지 보기", 안내는 "가운데 캘린더에서 종료일까지 남은 날을 세어 보세요. 왼쪽 임박 일정은 같은 일정을 남은 일수로 보여줍니다."다. "오늘 옮기기"의 "하루 전"·"하루 뒤", 요일을 포함한 현재 "오늘", "처음으로"를 제공하고 처음 날짜 기준 앞뒤 7일로 제한한다. "오늘" 변경은 임박 일정의 남은 일수·목록과 캘린더의 오늘 표시에 함께 반영한다. 응답 보기는 두지 않는다. 색은 프로젝트의 `plum`, 표시 문구는 "바꾸기 전 화면의 실제 코드 · 샘플 일정"이다. 캡션은 "2026년 8월 3일에 바꾸기 직전의 첫 화면입니다. 일정을 날짜 칸에 놓으면 무엇이 먼저 끝나는지 한눈에 들어오지 않아, 가운데 자리를 보상과 오늘 할 일로 바꿨습니다."다.
- **서비스 색·폰트·제목**: 서비스 루트의 `--oshi-*` 변수와 원본 임의 색으로 어두운 서비스 화면을 유지해 포트폴리오 테마에 따라 바뀌지 않게 한다. 전역 `@theme`에는 더하지 않는다. 원본 Pretendard와 크기를 유지하며 원본 `main`은 `div`로, 제목은 상세 페이지의 제목 계층에 맞춰 옮긴다.
- **에셋**: [games](../public/images/projects/oshi-calendar/games)의 게임 그림 5개만 쓴다. 원본 최대 표시 크기 40px의 두 배인 `80 × 80px` WebP(품질 80)로 줄여 합계 10,958바이트(약 10.7KiB)이며 데모 에셋 500KB 기준 안에 든다.

### 바탕화면과 큐레이터 커서

사이트 전체를 창 하나로 보여주는 연출을 바탕화면까지 넓혔다. `lg`(64rem) 이상에서만 쓰고, 모바일 · 태블릿 화면은 바뀌지 않는다.

- **바탕화면 아이콘**([DeskIcons](../src/components/desk/DeskIcons.tsx)): 창 왼쪽 76px 열에 포트폴리오 · 프로젝트 · 경력 · 교육 경험 · GitHub · 연락처 아이콘을 둔다. 마우스는 한 번 눌러 고르고 두 번 눌러 열고, 키보드(Enter · Space)와 터치는 한 번에 연다. 페이지 바로가기는 그 페이지를 연 탭이 있으면 그 탭으로, 없으면 새 탭으로 연다. DOM에서는 창 뒤에 두어 Tab 순서가 창의 크롬부터 시작한다.
- **첫 방문 연출**([intro.ts](../src/lib/intro.ts), [Curator](../src/components/desk/Curator.tsx)): 홈으로 처음 들어오면 창 없이 아이콘만 있는 바탕화면에서 연출 커서가 나타나 Figma 커서 채팅처럼 인사를 한 글자씩 타이핑하고([curator.ts](../src/data/curator.ts)), 포트폴리오 아이콘으로 가서 더블클릭한다. 창은 그 아이콘 자리에서 0.3배 → 1배로 펼쳐진다(440ms). 전체 약 6초이고, 아무 키나 누르거나 화면을 누르거나 "건너뛰기"를 누르면 바로 창이 열린다. 본 뒤에는 `localStorage`의 `intro-seen`으로 다시 재생하지 않는다.
- **연출 조건**: `lg` 이상, `prefers-reduced-motion` 없음, 홈(`/`)으로 들어온 첫 방문. 이력서 링크로 상세 페이지에 바로 온 방문자는 기다리게 하지 않는다. 창을 숨기는 일은 테마처럼 `<body>` 안 동기 스크립트가 첫 페인트 전에 `data-intro`로 하고, 하이드레이션까지 아무도 이어받지 않으면 8초 뒤 스스로 푼다. 저장소 접근이 막힌 환경에서는 매번 재생하지 않도록 건너뛴다.
- **큐레이터 커서**: 방문자를 안내하는 연출 커서다. 연출 뒤에는 아이콘 아래에서 움직이지 않고 쉰다. 방문자의 커서를 따라다니지 않는다. 부가 설명이 필요한 자리는 `curator.say({ text, target })`([curatorChannel.ts](../src/components/desk/curatorChannel.ts))로 부르면 그 요소 곁으로 다가가 말하고 돌아온다. 방문자가 스크롤하면 말을 접는다. 지금 이 호출을 쓰는 자리는 [라이브 탭](#live) 하나다.
- **클랩**: 방문자 커서가 큐레이터에 부딪히면 서로 다가갔다 튕기며(420ms) 부딪힌 자리에 Accent 선 8개가 퍼지고, 말풍선이 "짝!" 같은 반응을 차례로 말한다. 0.9초 간격을 둔다.
- **색**: 커서 · 이름표 · 말풍선은 루트 색맥락(Mocha)의 `hue-deep` 바탕에 `paper` 글자, 손뼉 선은 글자가 닿지 않는 장식이라 Accent다. 그림자는 쓰지 않는다.
- **접근성**: 커서와 말풍선은 장식(`aria-hidden`)이다. 연출 동안 인사 전체를 `role="status"`로 한 번 읽히고, 건너뛰기 버튼을 둔다. 연출 커서의 움직임은 JS가 맡으므로 모션 감소 설정에서는 연출을 재생하지 않고, `say`의 이동은 바로 옮기며 클랩은 말풍선만 바뀐다.

### 라이브 탭

배포된 실제 서비스를 캡처 대신 창 안에서 그대로 연다. 창 · 탭 · 주소창 연출이 "서비스를 여는 일"까지 이어지게 하는 자리다. 경로는 `/live/[slug]`이고 [projects.ts](../src/data/projects.ts)에서 `live`를 켠 프로젝트만 대상이다.

- **대상**: syu-likelion(공개 화면), 삼육대 어디야, Oshi Calendar, mathGraph. 네 서비스 모두 다른 사이트 안에서 열리는 것을 2026-11-18에 응답 헤더(`X-Frame-Options` · `Content-Security-Policy` 없음)와 실제 화면으로 확인했다. 서비스 쪽에서 막으면 빈 화면이 되므로 `live`를 끄고 서비스 링크를 새 창 링크로 되돌린다. 로그인 뒤 화면이나 종료된 서비스(Make A Wish)는 대상이 아니다.
- **여는 길**: `md` 이상에서 프로젝트의 "서비스 열어 보기"가 현재 탭에서 이 경로로 간다. 주소창에 서비스 주소(`syu-likelion.org`)를 입력해도 같은 탭이 열리고, 새 탭 시작 페이지에 "실제 서비스" 바로가기가 있다. 뒤로 버튼으로 돌아간다.
- **주소창 · 탭**: 주소창은 `/live/eodiya` 대신 `tim3208.github.io/eodiya`처럼 서비스의 실제 주소를 보여주고, 탭 제목은 `이름 · 서비스`다. 표는 서버의 [BrowserWindow](../src/components/browser/BrowserWindow.tsx)가 조립한다. 등록되지 않은 바깥 주소는 지금처럼 `/external` 안내로 간다.
- **배치**: 한 줄 안내(실제 서비스 · 이름 · 해 볼 것 한 가지 · 작업 과정 읽기 · 새 창에서 열기) 아래를 서비스가 채운다. 섹션 높이는 `--viewport-height`(화면 − 창 바깥 여백 − 크롬 84px)라 서비스가 본문 영역을 꼭 채우고, 연락처는 그 아래로 스크롤하면 나온다. 이 변수는 [BrowserWindow](../src/components/browser/BrowserWindow.tsx)의 여백 · 크롬 높이와 함께 바꾼다. 서비스 화면에는 테두리 · 그림자 · 기기 프레임을 더하지 않는다.
- **불러오기**: 서비스가 뜨기 전에는 주소와 "불러오는 중입니다"를 보여주고, 다 불러오면 200ms 투명도 전환으로 서비스가 나타난다. 12초가 지나면 새 창에서 열 수 있다고 알린다. 새로고침 버튼은 서비스를 다시 불러온다.
- **모바일**: 창이 없는 `md` 미만에서는 서비스를 불러오지 않는다(화면 안의 화면이 되어 스크롤이 갇힌다). 서비스 링크는 이 경로를 거치지 않고 실제 새 창으로 열리고, 주소를 직접 입력해 들어온 경우에는 새 창으로 여는 버튼을 보여준다.
- **큐레이터**: 서비스가 열리면 큐레이터가 화면 왼쪽 위로 다가와 한마디 하고 돌아간다([curator.ts](../src/data/curator.ts)의 `live`). 들어와 있는 동안 한 번만 한다.
- **보안**: `sandbox`로 안의 페이지가 이 창 전체를 다른 주소로 보내지 못하게 한다. 서비스가 쓰는 스크립트 · 저장소 · 폼 · 새 창 · 내려받기 · 알림창은 허용한다. 주소는 서버가 정한 표에서만 나오고 방문자가 입력한 주소를 `src`로 쓰지 않는다.
- **접근성**: 페이지의 `h1`은 프로젝트 이름이다. 서비스 화면은 `title`을 가진 `iframe`이고, 불러오는 상태는 `role="status"`로 읽힌다. 다 불러오면 뒤에 남은 주소 · 상태 글자는 접근성 트리에서 뺀다.

<a id="hero"></a>

### 홈 첫 화면(HERO)

방문자가 들어와 몇 초 안에 "웹 개발자 박정우의 포트폴리오다 → 불편을 발견해 실제 웹 서비스로 해결하는 개발자다 → 운영 플랫폼 · 축제 서비스 · 지도 · 대시보드처럼 성격이 다른 서비스를 만들었다 → 고르거나 내려가면 작업 과정을 볼 수 있다"를 읽게 하는 자리다. 역할을 둘로 나눈다.

| 자리 | 맡는 것 | 하지 않는 것 |
| --- | --- | --- |
| HERO | 정체성(직무 · 이름), 작업의 방향(메인 문구 · 소개 한 문장), 프로젝트의 다양성(대표 4개를 같은 크기로) | 한 프로젝트를 크게 키우기, 문제 · 기술 · 성과 노출 |
| 대표 프로젝트(Featured Work) | 개별 사례의 문제 · 판단 · 구현 · 결과. 첫 항목 syu-likelion을 가장 깊게(운영진 화면 전환 + 주석, 화면 8 : 설명 4) | HERO와 같은 화면을 연달아 크게 반복하기 |

- **위계**: `h1` 하나가 `Web Developer 박정우` · 메인 문구(`PROFILE.headline`, `--text-hero` 1440px에서 약 68px)를 순서대로 담는다. 메인 문구가 가장 크고, 직무 · 이름이 그 바로 위에서 함께 읽힌다. 소개 한 문장(`PROFILE.intro`)과 CTA(프로젝트 둘러보기 → `#featured`, GitHub, 연락처)는 `lg` 이상에서 오른쪽에 바닥을 맞춰 둔다. 등장 애니메이션 없이 처음부터 읽힌다.
- **프로젝트 목록**([ProjectIndex](../src/components/project/ProjectIndex.tsx)): 대표 프로젝트를 데이터 순서대로 최대 4개, 같은 크기의 칸으로 둔다. 칸에는 실제 화면의 한 부분과 이름 · 서비스 종류(`Project.preview.label`)만 있고, 칸 전체가 Case Study 링크 하나다. 브라우저 목업 프레임은 씌우지 않는다.
- **같은 화면 반복 피하기**: `Project.preview`는 대표 프로젝트 행과 다른 화면이나 다른 부분을 고른다. syu-likelion은 공개 모집 안내 화면(아래 행은 운영진 화면), 삼육대 어디야는 지도 부분(아래 행은 검색 패널까지 전체), Oshi Calendar는 종료 임박 일정 · 오늘 할 일 부분이다. 칸 비율이 화면 폭마다 달라도 같은 부분이 남고, Oshi의 계정 영역(이메일)은 어느 비율에서도 잘려 나가도록 `position`을 골랐다.
- **HERO 화면 캡처가 없는 프로젝트**: `preview.src`가 없으면 빈 칸에 이름 · 운영 시점만 둔다. "화면 준비 중" 같은 작업 상태는 적지 않는다. 지금은 해당하는 프로젝트가 없다. Make A Wish 칸은 상세 스탬프 데모의 서비스 화면(정상 응답 · 샘플 부스 3개)을 2026-11-19에 캡처한 `make-a-wish.png`이고, 세로 화면이라 `position`으로 안내 문구와 채워진 별이 보이는 부분을 고른다.
- **크기**: `lg` 이상 4열, 그 아래 2 × 2. 칸 비율은 모바일 3 : 4, `md` 1 : 1, `lg` 이상 4 : 5이고, 넓은 화면에서는 `max-height: calc(100dvh − 32rem)`(최소 16rem)로 막아 창 높이에서 크롬 · 문구 높이를 뺀 만큼만 키운다. HERO 높이를 100vh로 고정하지 않는다. 1440 × 900, 1280 × 800, 1024 × 768에서 메인 문구 · 직무 · 4개 칸의 이름 · 서비스 종류까지 첫 화면에 들어오고(2026-10-10 실측), 1920 × 1080에서는 칸이 4 : 5 그대로 커진다.
- **선택(인터랙션)**: 레퍼런스(GSAP Vault developer portfolio)의 "포인터 · 포커스가 닿은 프로젝트만 그 색으로 선택되고 화면이 앞으로 나오는" 방식을, 한 장이 앞을 독점하는 화면 겹침 대신 같은 크기의 칸으로 옮겼다. 쉴 때는 모든 칸이 무채색으로 같은 무게다. hover · 키보드 포커스가 닿은 칸 하나만 프로젝트 색 테두리 2px, 이름 밑 tint 면(텍스트를 고른 듯한 표시), "작업 과정 보기" 표시가 나타나고 화면이 1.045배 다가온다(260ms). 나머지 칸은 투명도 0.55 · 채도 0.4로 물러난다. 한 번에 한 프로젝트 색만 보이므로 [한 섹션 한 색](#hue) 원칙을 지킨다.
- **터치 · 모션 감소**: 이름과 서비스 종류는 늘 보이므로 hover가 없는 화면에서도 정보가 같고, 탭하면 바로 Case Study로 간다. `prefers-reduced-motion: reduce`에서는 확대와 전환 없이 색 · 테두리로만 선택을 알린다. 자동으로 넘어가는 캐러셀, 패럴랙스, 3D, HERO 자체의 등장 연출은 쓰지 않는다(첫 방문 창 열기 연출은 [바탕화면과 큐레이터](#intro)). 애니메이션 라이브러리는 추가하지 않았다.
- **내부 브라우저**: 홈 탭 제목은 "박정우 포트폴리오"로 이 창이 누구의 포트폴리오인지 말한다(내비 링크 이름은 "홈" 그대로). 탭 · 주소창 · 뒤로 · 앞으로 · 새로고침 동작은 바꾸지 않았다.

### 남은 제한

- 공개 사이트와 비교한 실측, 200% · 400% 확대, 실기기 터치는 확인하지 않았다.
- Make A Wish의 대표 행·상세 지도 화면 캡처, mathGraph 결과물 캡처는 확보 전이다. Make A Wish 상세 스탬프와 Oshi Calendar 바꾸기 전 첫 화면은 원본 코드와 샘플 데이터로 실행한다. 삼육대 어디야 · Oshi Calendar는 공개 화면이 한 장씩이라 HERO와 대표 행이 같은 캡처의 다른 부분을 쓴다. 다른 화면(검색 결과 목록, 게임 허브 등)을 더 확보하면 HERO 칸을 바꾼다. mathGraph는 좌표와 표시 글자를 분리한 판단을 샘플 도식([CoordinateLabel](../src/components/project/CoordinateLabel.tsx))으로만 보여준다.
- 모바일에서는 데스크톱 캡처를 축소해 보여주고 "원본 크기로 보기" 링크로 확대 경로를 둔다. 핵심 영역만 다시 자른 모바일용 캡처는 후속 작업이다.

<a id="direction"></a>

## Direction

이 사이트는 이름, 실제로 만든 화면, 본인이 맡은 일이 먼저 보이는 프론트엔드 개발자 포트폴리오다. 국내 채용 담당자가 프로젝트의 문제·판단·구현·확인된 결과를 읽을 수 있게 한다.

판단 기준은 Clean, Product-oriented, Editorial, Minimal, Professional, Developer + Product Design이다. Linear, Vercel, Toss Tech처럼 절제된 제품 문서의 방향을 참고하되 특정 사이트를 복제하지 않는다.

피해야 할 것은 기술 아이콘 대량 나열, 의미 없는 Three.js, 네온/터미널 스타일, 커서 추적, 모든 섹션의 카드화, 과한 배지, 근거 없는 "Innovative / Passionate / Creative" 카피, 임의 Skill Percentage다.

프로젝트 설명은 기능 목록보다 문제, 판단, 해결, 결과의 흐름을 먼저 보여준다.

<a id="layout"></a>

## Layout

전체 사이트는 하나의 브라우저 창이 데스크 위에 떠 있는 구조다. 창은 화면 폭을 거의 다 쓰고(바깥 여백 12 · 16 · 20px) 최대 1760px(`--container-window`)에서 멈춘다. 1920 화면이라면 양쪽에 80px씩 데스크가 남는다. 창과 크롬은 [BrowserWindow](../src/components/browser/BrowserWindow.tsx)가 소유하고, 창 안 본문 스크롤은 [Viewport](../src/components/browser/Viewport.tsx)가 맡는다. 데스크톱에서 창은 화면 높이에 고정되며 실제 문서는 스크롤되지 않는다.

Case Study는 Text, Screenshot, Diagram, Metric을 섞어 구성한다. 텍스트만 길게 이어지는 페이지를 피하고, 각 섹션은 하나의 메시지만 갖는다.

Home은 스토리형 요약이다. 스크롤 순서가 핵심 메시지 순서와 같다: 소개 → 대표 프로젝트(첫 항목을 가장 크게, 나머지는 이미지·설명이 나란한 행) → AI와 일하는 방식 → 교육 경험 → 경력 → 그 밖의 프로젝트. 모든 섹션은 데이터에서 목록을 받아 그리고, 비어 있으면 섹션째 그리지 않는다. 서로 다른 경험의 수치를 모은 레일은 사용하지 않고, 수치는 각 프로젝트·교육 블록 안에 둔다. 섹션 제목은 내비게이션의 페이지 이름과 같은 한국어를 쓴다(교육 경험 · 경력). 홈에 두는 것과 다른 페이지로 넘기는 것은 [콘텐츠 기준](content.md#projects)의 표를 따른다.

문제 · 판단 · 결과처럼 같은 형식으로 비교하는 문장은 [Labeled](../src/components/project/ProjectParts.tsx)로 쓴다. 두 글자 한국어 라벨을 왼쪽 칸(36px)에, 문장을 오른쪽에 두어 여러 줄이 이어질 때 라벨끼리 세로로 맞는다.

Work는 대표 프로젝트 행, 보조 프로젝트 비교 목록(넓은 화면에서 나의 역할·프로젝트 소개·확인된 결과 칸을 세로로 맞추고 좁은 화면에서는 칸 이름을 붙여 쌓음), 그 밖의 프로젝트 순서로 구성한다. 상세 첫 화면에는 출발한 불편과 내가 맡은 것·팀이 맡은 것을 나란히 둔다. 상세 Hero는 프로젝트 이름, 설명, 역할·기간·팀·성과를 먼저 제시하며 syu-likelion에는 실제 랜딩 화면을 둔다. 모든 섹션을 같은 작은 영문 라벨·큰 제목·설명·구분선 조합으로 반복하지 않는다.

폭과 여백은 책임을 나눠 한 곳에서만 준다. 창 셸은 창 폭 · 바깥 여백 · 크롬, [Container](../src/components/ui/Container.tsx)는 섹션 거터, 문단은 읽기 폭, [Shot](../src/components/ui/Shot.tsx)은 화면비 · 잘림 · 주석을 맡는다. 매체를 다시 패딩 카드에 넣어 화면을 줄이지 않는다. 데모처럼 상태를 묶는 실제 UI 그룹에만 안쪽 패딩을 둔다.

| 토큰 · 값 | 용도 |
| --- | --- |
| `--container-window` `110rem` | 창 최대 폭 1760px |
| `md:p-3` · `lg:p-4` · `2xl:p-5` | 창 바깥 여백 12 · 16 · 20px |
| `px-4` · `md:px-6` · `2xl:px-8` | 섹션 거터 16 · 24 · 32px (Container) |
| `--container-measure` `42rem` | 긴 문단 읽기 폭 672px |
| `py-14` · `md:py-20` | 주요 섹션 간격 56 · 80px |
| `lg:grid-cols-12` 8 : 4 · `xl` 7 : 5 | 홈 HERO 메인 문구 : 소개 · CTA. 그 아래 대표 프로젝트 4열(`lg`), 2 × 2(그 아래) |
| `lg:grid-cols-12` 8 : 4 | 대표 프로젝트 첫 항목(syu-likelion) 화면 : 설명 |
| `lg:grid-cols-12` 7 : 5 | 대표 프로젝트 행 화면 : 설명 (행마다 좌우 교대) |
| `xl:grid-cols-[12rem_1fr]` | Case Study 고정 목차 : 본문. `xl` 미만은 본문 위 인라인 목차 |

1440 × 900 화면에서 실측한 값은 Viewport 1393px, 섹션 내용 폭 1345px(96.6%), 크롬 2행 84px이다(2026-10-10, 개발 서버). 원본보다 크게 늘리면 UI 글자가 흐려지므로 스크린샷은 원본 폭을 넘기지 않는다.

<a id="typography"></a>

## Typography

타이포그래피는 전달을 우선한다. 우선순위는 강한 Heading, 읽기 쉬운 Body, 명확한 Metadata, 작은 Label 순서다.

[layout.tsx](../src/app/layout.tsx)는 Pretendard와 JetBrains Mono를 self-host한다. 본문·설명·제목·역할·라벨은 Pretendard를 사용하고, 모노 폰트는 코드·날짜·수치에 한정한다. [실제 코드 실행 데모](#option-3-demos)의 옮긴 서비스 화면은 원본을 따라 스탬프는 Hahmlet, 삼육대 어디야는 시스템 sans-serif를 사용한다.

| 토큰 | 값 | 역할 |
| --- | ---: | --- |
| `--text-display` | `clamp(2rem, 1.35rem + 2.2vw, 3.25rem)` | 페이지 `h1` — 모바일 32 · 데스크톱 52px |
| `--text-title` | `clamp(1.625rem, 1.35rem + 0.9vw, 2rem)` | 섹션 제목 26–32px |
| `--text-lead` | `1.125rem` | 리드 문단 · 판단 문장 18px |
| `text-base` | `1rem` | 기본 본문, 행간 1.7 |
| `text-sm` | `0.875rem` | 보조 설명 · 메타데이터 · 화면 주석 · 문제/판단/결과 라벨 14px |
| `text-xs` | `0.75rem` | 기술 목록, 상세 정보 칸 이름, 데모 안의 짧은 라벨 |

주요 한국어 설명은 16px(`text-base`)로 읽히게 한다. 한글 본문은 `word-break: keep-all`을 기본으로 하고, 수치에는 `tabular-nums`로 자릿수를 맞춘다. 제목 위에 같은 뜻의 영문 라벨(eyebrow)은 생략한다. 상세 제목과 목차에서는 장식 번호를 표시하지 않되 기존 섹션 앵커는 보존한다.

<a id="color"></a>

## Color

팔레트는 중성 지면, 여섯 색 계열, 장식용 Accent 하나로 고정한다(2026-11-18 변경. 이전 값은 Cloud Dancer 지면과 Earthen Pastels였다). 지면과 글자는 색을 띠지 않는 회색이고, 색은 여섯 계열만 맡는다. 포트폴리오 UI에는 순백 `#FFFFFF`을 사용하지 않는다. [실제 코드 실행 데모](#option-3-demos)의 옮긴 서비스 화면은 실제 스크린샷과 같은 색 예외다.

색은 장식이 아니라 정보 구조다. 섹션마다 하나의 hue를 걸고, 링크, 수치, 포커스링, 식별 바가 같은 색맥락을 공유한다. 여섯 계열은 밝기(지면 위 대비)는 같고 색상만 달라, 섹션이 바뀌면 색이 바뀐 것이 보인다. 색을 새로 추가하려면 `#F7F7F5`와 `#101113` 양쪽 대비를 실제로 계산한다.

## Hue

한 섹션에는 `.hue-*` 클래스를 하나만 건다. 실제 클래스는 [hue.ts](../src/lib/hue.ts)의 `HUE_CLASS`가 관리한다.

| hue | CSS scope |
| --- | --- |
| `mocha` | `.hue-mocha` |
| `terracotta` | `.hue-terracotta` |
| `wheat` | `.hue-wheat` |
| `sage` | `.hue-sage` |
| `plum` | `.hue-plum` |
| `blush` | `.hue-blush` |

`.hue-*`는 `--hue-wash`, `--hue-tint`, `--hue-deep`을 바꾼다. 하위 컴포넌트에서 색맥락에 따라 바뀌어야 하는 색은 `bg-hue-wash`, `bg-hue-tint`, `text-hue-deep`, `border-hue-deep` 별칭으로 사용한다. 본문과 지면에는 해당 역할의 ink·paper 토큰을 유지한다.

여섯 색이 한 화면에 모두 모이는 곳은 Contact 하단 색표본 스트립과 OG 이미지뿐이다. 스트립은 도색 단계에서 [Footer](../src/components/layout/Footer.tsx)에 `--color-strip-*`로 다시 둔다. OG 색은 [og.ts](../src/lib/og.ts)에 고정되어 있다.

<a id="contrast"></a>

## Contrast

`deep` 6종은 지면(`#F7F7F5`) 위에서 `6.55 : 1`부터 `6.64 : 1` 범위로 맞춘다. 편차는 `0.1` 이내다. 같은 계열의 wash 위에서는 `6.15 ~ 6.22 : 1`, tint 위에서는 `5.06 ~ 5.25 : 1`을 지킨다. 버튼처럼 deep 면에 지면색 글자를 올릴 때도 같은 `6.55 : 1` 이상이다.

| tint 위 허용 색 | 대비 기준 |
| --- | ---: |
| `--color-ink` | `12.9 ~ 13.5 : 1` |
| `--color-ink-2` | `7.1 ~ 7.4 : 1` |
| `--hue-deep` | `5.06 ~ 5.25 : 1` |

`--color-ink-3`는 tint 위에서 `4.1 ~ 4.3 : 1`로 떨어지므로 쓰지 않는다. wash 위에서는 `5.0 : 1`이라 쓸 수 있다.

<a id="color-prohibitions"></a>

## Color Prohibitions

- 그라디언트를 쓰지 않는다. wash와 tint는 언제나 단색 면이다.
- 한 섹션에 두 계열 이상을 섞지 않는다.
- 여섯 색을 본문이나 Heading 색으로 쓰지 않는다. 지면과 본문 글자에는 색을 넣지 않는다.
- tint 위에 `--color-ink-3`를 올리지 않는다.
- 색만으로 정보를 전달하지 않는다. 프로젝트 색에는 항상 이름을 함께 둔다.
- 대비 범위를 벗어나는 색을 추가하지 않는다.
- JSX에 색상 hex를 하드코딩하지 않는다. 색은 토큰, hue 데이터, OG 토큰 중 하나에서 온다.

<a id="dark-theme"></a>

## Dark Theme

다크 테마는 반전이 아니라 역할 교체다. 밝은 중성색은 지면에서 잉크로 올라오고, 여섯 색은 다크 지면에서 읽히는 값으로 다시 정의된다.

다크 값은 `@media (prefers-color-scheme: dark)`의 `:root:not([data-theme="light"])`와 `:root[data-theme="dark"]`에 같은 값으로 둔다. `.hue-*` 스코프와 컴포넌트 CSS는 바꾸지 않는다.

| 묶음 | 다크 값 |
| --- | --- |
| 지면/잉크 | `--color-paper #101113`, `--color-paper-raised #17181B`, `--color-paper-sunk #0A0A0B`, `--color-deep-ground #050506`, `--color-ink #F3F3F1`, `--color-ink-2 #B3B6BC`, `--color-ink-3 #8A8D94`, `--color-rule #25272B`, `--color-rule-strong #3A3D43` |
| Mocha | `#21170F`, `#4D2E14`, `#EDA975` |
| Terracotta | `#231613`, `#512A24`, `#F8A293` |
| Wheat | `#1C1A0E`, `#3F370C`, `#C9B966` |
| Sage | `#121C14`, `#1D3F26`, `#82C891` |
| Plum | `#1D1721`, `#412D4D`, `#D2A8EC` |
| Blush | `#221519`, `#502934`, `#F59FB7` |
| 창 프레임 | `--color-desk #050506`, `--color-chrome #17181B`, `--color-omnibox #1E2024`, `--color-accent #D98A5F`, `--window-shadow 0 0 0 1px #3A3D43, 0 24px 60px -24px rgb(0 0 0 / 0.8)` |

다크의 `deep` 6종은 `#101113` 위에서 `9.47 : 1 ~ 9.55 : 1`로 맞춘다. tint 위에서는 `5.93 ~ 6.20 : 1`이고, `--color-ink-3`는 다크에서도 tint 위에 올리지 않는다(`3.5 ~ 3.7 : 1`). 두 다크 블록의 18개 색 계열 토큰과 창 프레임 5개 값을 함께 유지한다. Contact/Footer의 `--color-deep-ink`, `--color-deep-ink-2`, 여섯 `--color-strip-*`는 테마와 무관한 상수다.

테마 상태는 셋이다. 시스템은 `data-theme` 없음, 라이트 고정은 `data-theme="light"`, 다크 고정은 `data-theme="dark"`다. 시스템 상태에서 속성이 없어야 OS 다크 모드를 따른다.

[theme.ts](../src/lib/theme.ts)의 동기 초기 스크립트는 `<body>` 첫 자식에 두고 첫 페인트 전에 저장된 라이트·다크 값이 있을 때만 `data-theme`를 붙인다. [ThemeToggle](../src/components/layout/ThemeToggle.tsx)은 DOM의 `data-theme`를 단일 출처로 삼는다. `next-themes`를 도입하지 않는 프로젝트의 이유는 시스템 상태에서도 속성을 비워 두는 현재 CSS 계약을 유지하기 위해서다.

<a id="accent"></a>

## Accent

Accent는 장식면 전용이다. 라이트 값은 `#C8683A`, 다크 값은 `#D98A5F`이다.

`#C8683A`는 지면 위에서 `3.56 : 1`이고, `#F7F7F5` 글자를 올려도 `3.56 : 1`이다. 본문 색, 링크 색, 버튼 배경으로 쓰지 않는다.

허용 위치는 탭 활성 라인, 신호등 점, 식별 바, 보더처럼 글자가 닿지 않는 면이다. 텍스트, 링크, 버튼 배경이 필요하면 `--color-mocha-deep` `#884700`을 쓴다. 라이트 버튼은 `bg-mocha-deep` + `text-paper` 조합으로 `6.64 : 1`을 확보한다. 리뷰에서는 `text-accent`와 글자가 있는 `bg-accent` 사용을 확인한다.

<a id="motion"></a>

## Motion

모션은 기능 상태의 피드백과 설명용 데모, 그리고 [바탕화면 · 큐레이터 연출](#intro)에만 쓴다. 기능을 기다리게 하지 않고, 초기 콘텐츠는 등장 연출 없이 바로 보인다. 예외는 홈 첫 방문의 창 열기 연출 하나이며, 언제든 키 하나로 건너뛸 수 있다. 전역 문단 fade-up · section reveal은 쓰지 않는다.

| 상호작용 | 동작 | 시간 |
| --- | --- | --- |
| 링크 · 버튼 · 탭 피드백 | 색 · 밑줄 색 변화 | 150ms |
| 화면 주석 강조 | 짝이 되는 점 확대 · 목록 번호 채움 | 140ms |
| 화면 전환 · 기존 두 재구성 데모 | 겹친 패널의 투명도 전환 | 180ms |
| 라이브 탭 | 다 불러온 서비스가 투명도 전환으로 나타남 | 200ms |
| HERO 프로젝트 선택 | 선택 칸 확대 1.045 · 테두리 · 이름 밑 면, 나머지 칸 물러남 | 160–260ms |
| 첫 방문 창 열기 | 큐레이터 인사 타이핑 → 아이콘 더블클릭 → 아이콘 자리에서 창이 펼쳐짐 | 약 6초, 창 440ms |
| 큐레이터 이동 · 클랩 | 휘어진 경로 이동, 부딪힘 반동 · 손뼉 선 | 700–900ms, 420–480ms |

금지 범위는 scroll hijacking, 과한 parallax, cursor follower(큐레이터는 방문자 커서를 따라다니지 않는다), 지속적인 background animation, 자동 슬라이드, 읽기를 방해하는 움직임이다. `prefers-reduced-motion: reduce`에서는 animation · transition · smooth scroll을 사실상 끄고([globals.css](../src/app/globals.css) 맨 아래), 선택 결과와 설명은 그대로 바뀐다.

<a id="responsive"></a>

## Responsive

| 항목 | 규칙 |
| --- | --- |
| 창 연출 | `md`(48rem) 이상에서만. 모바일은 창 테두리·크롬 없이 일반 페이지 |
| 데스크 여백 | `12px` at `48rem`, `16px` at `64rem`, `20px` at `96rem`. `64rem` 이상은 왼쪽에 바탕화면 아이콘 열(76px + 12px)이 더 붙는다 |
| 창 폭 | 최대 `1760px`. 본문 전체의 최대 폭은 없고 긴 문단만 `672px` |
| 데스크 크롬 | 탭줄(탭·닫기·새 탭) + 도구줄(뒤로·앞으로·새로고침·주소창·주요 페이지·연락처·GitHub·테마) 2행. GitHub은 `lg` 이상 |
| 모바일 상단 | 이름·테마 토글 + 주요 페이지 링크. 문서 전체가 스크롤된다 |
| 라이브 탭 | `md` 이상에서만 서비스를 창 안에 연다. 모바일은 실제 새 창으로 연다 |

모바일에서 창 연출을 푸는 이유는 실제 브라우저 주소창과 디자인한 주소창이 겹치고, 고정 창 안의 이중 스크롤이 모바일 브라우저의 주소창 접힘과 충돌하기 때문이다. 모바일에서도 가로 넘침을 막고 Case Study 이미지를 세로로 쌓는다. 햄버거 메뉴로 대체하지 않는다. 데스크톱 캡처는 축소되므로 화면 주석 목록과 "원본 크기로 보기" 링크로 읽을 길을 둔다. 320px에서 주요 경로 12개의 가로 넘침이 없음을 확인했다(2026-10-10).

<a id="accessibility"></a>

## Accessibility

기본 원칙은 semantic HTML, keyboard navigation, focus state, 충분한 contrast, 이미지 alt, 명확한 button/link 목적, heading hierarchy, reduced motion 대응이다.

구현 규칙은 다음과 같다.

- 창 안의 탭은 방문자가 연 페이지이므로 링크가 아니라 `<button>`이다. 활성 탭에 `aria-current="page"`를 붙인다. `role="tab"`과 `role="tablist"`는 쓰지 않는다.
- 탭 닫기 버튼의 접근 이름은 `○○ 탭 닫기`다.
- 주소창은 실제 `<input>`이고 `label`을 가진다. Enter로 이동하고 Escape로 원래 주소로 돌아간다. 주소 입력 후에는 본문(`#content`)으로 초점을 옮긴다. 새 탭 시작 페이지에서는 주소창이 초점을 받는다.
- 뒤로·앞으로는 활성 탭의 방문 기록이 없으면 `disabled`가 된다.
- skip link는 [layout.tsx](../src/app/layout.tsx)의 `#content`를 향한다. `main`의 `tabIndex={-1}`은 링크 실행 시 본문으로 포커스를 옮기되 일반 Tab 순서에는 추가하지 않는다.
- 확보할 화면 자리 [Placeholder](../src/components/ui/Placeholder.tsx)는 `role="img"`와 들어갈 화면의 설명을 가진다.
- 화면 주석의 점은 장식(`aria-hidden`)이고, 같은 내용이 "화면 주석" 번호 목록으로 읽힌다.
- 화면 전환·기존 두 재구성 데모·스탬프 데모의 상황 선택은 `fieldset` + `legend` 안의 라디오 묶음이다. 선택 상태는 굵기 · 아래 선 · 면 변화로 함께 보여 색에만 기대지 않는다.
- 포커스링은 섹션 색맥락의 `--hue-deep` 2px 외곽선이다. 옮긴 스탬프 서비스 화면 안에서는 원본의 `#2d7dc8` 2px 표시를 쓴다.
- 크롬 아이콘 버튼은 `뒤로` · `앞으로` · `새로고침` · `새 탭` · `○○ 탭 닫기` 접근 이름을 가지고, 테마 토글은 현재 상태와 다음 동작을 접근 이름 · 툴팁으로 말한다.

<a id="browser-frame"></a>

## Browser Frame

창 프레임은 `--window-shadow`의 1px 링 하나로 테두리를 대신한다. 둥근 모서리는 창 셸에 `overflow`를 주지 않고 크롬(위)과 Viewport(아래)가 각자 맞춘다. 창 셸에는 `overflow` · `transform` · `filter`를 주지 않는다. 예외는 [첫 방문 창 열기](#intro) 애니메이션 440ms 동안의 `transform`이며, fill 없이 끝나면 사라진다.

브라우저 창 프레임은 AI 디자인 느낌 줄이기 규칙의 유일한 예외다. 사이트 전체가 하나의 창으로 읽혀야 하므로 창 하나에 필요한 radius와 shadow만 허용한다.

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `--radius-window` | `0.75rem` / `12px` | 창 하나 (바깥 여백이 12–20px로 줄어 함께 줄였다) |
| `--radius-panel` | `0.5rem` / `8px` | 탭, 주소창, 전환 컨트롤 바탕 |
| `--radius-chip` | `0.375rem` / `6px` | 토글, 작은 컨트롤 |
| `--window-shadow` | light shadow 또는 dark ring | 창 하나 |
| `--viewport-height` | `100dvh` − 바깥 여백 − `5.25rem` | 창 안 본문 높이. [라이브 탭](#live)의 높이, [스탬프 데모](#option-3-demos)의 화면 폭, 넓은 화면 데모의 프레임 높이 제한에 쓴다 |

그림자는 창 하나에만 사용한다. 다크 오버라이드가 적용되도록 `--window-shadow`는 `@theme`이 아니라 `:root`에 두고 `shadow-(--window-shadow)`로 소비한다. 창 높이는 고정이고 본문 스크롤은 Viewport가 맡으므로, 크롬은 sticky가 아니라 창 상단에 그대로 놓인다. 앵커 이동도 Viewport 안에서 일어난다.
